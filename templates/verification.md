| # | 命令 | 结果 | 备注 |
|---|------|------|------|
| 1 | `npm test` | PASS | 45/45 |

| 3 | `npm run lint` | PASS | 0 错误 |
| 4 | `npm test -- integration/legacy` | PRE-EXISTING | 基线已失败,与本次变更无关 |

**规则:**
- 每条跑过的命令记一行,结果只允许 PASS / FAIL / PRE-EXISTING
- `PRE-EXISTING` = 仓库基线已知失败,标注短标识,不算本次失败,也不冒充本次通过
- 状态为 `passed` 前,不得宣称任何"完成";子代理报告只算声明,主会话须亲自复核关键命令

<purpose>

验证报告是**契约符合性的客观证据**。

**问题它解决:** 不知道"AI 实现的代码是否真的符合讨论阶段定下的契约"。

**解决方案:** 系统对照 OpenAPI(端点、schema、错误码)和流程图(事件链路、状态机),逐一检查。

**关键原则:** 客观、可重现——所有结论都有命令输出或文件引用支持。

**Fresh evidence 纪律:**

1. 每条命令记一行(命令 + PASS/FAIL/PRE-EXISTING),没有命令支撑的结论不写
2. 基线已知失败标 `PRE-EXISTING`,不冒充本次通过,也不算本次失败
3. 协调器的验证报告对主会话只是"声明"——主会话须亲自复核关键命令(至少测试 + 构建)后才算通过
4. 任何"完成"声明都在验证完成后做出;验证与独立评审严格串行,不并行

</purpose>
